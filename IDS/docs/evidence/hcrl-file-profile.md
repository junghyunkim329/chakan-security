# HCRL Car-Hacking 원본 파일 분석

분석 기준일: 2026-11-24

사용자가 제공한 `9) Car-Hacking Dataset.zip`에서 공격 CSV 4개와 별도 정상 주행 로그를 분석했다. **파일의 기술통계·품질 분석을 완료했으며, IDS 성능 검증과 가상 CAN 재생은 수행하지 않았다.**

## 입력과 확인 방법

- 출처 설명: [HCRL Car-Hacking Dataset](https://sites.google.com/hksecurity.net/hcrl/Datasets/car-hacking-dataset).
- 사용자 전달 경로: `/tmp/hcrl-car-hacking.zip`. 원본은 로컬 실행 결과의 `raw/`에 복사해 보관했다.
- ZIP SHA-256: `c47c139142e83965fc74e416d76eee76dc8de48b3d6c6b639e44b663484c8de9`.
- ZIP 내부 CRC 검사 통과. 제공기관 digest와 대조한 것이 아니므로 SHA-256은 이번 입력 식별값이다.
- 원본을 변경하거나 압축을 풀지 않고 스트리밍으로 읽었다. CSV의 가변 열과 정상 텍스트의 별도 형식을 처리했다.
- 정수 microsecond로 시각을 계산하고, 별도 검산으로 물리 행·T/R 건수와 최대 시간 공백을 확인했다. 1초 peak는 `(t−1초, t]`, 분위수는 nearest-rank다. IDS 임계값을 정한 것이 아니다.

## 제작·평가에 영향을 주는 관측

1. **네 공격 CSV에 공통 정상 suffix가 있다.** 마지막 891,068행·46,162,376 byte가 모두 같고 라벨은 전부 R이다. 이 구간의 SHA-256은 `262ef366bb19f322fa1fa415e5360d5b33cf242462841b1f2ad1faf464541fec`다. 파일 이름만 달리해 학습·평가로 나누면 같은 구간이 양쪽에 포함될 수 있다. 전체의 유일 행 수나 추가 중복까지 확정한 결과는 아니다.
2. **기록 공백을 공격으로 취급하면 안 된다.** 공통 suffix로 넘어가는 최대 간격은 DoS 22.358267초, RPM 7,744.934786초, gear 5,588.125845초, Fuzzy 2,539.482308초다. timestamp가 커졌다고 그동안 ECU가 공격으로 중단됐다고 판단하거나 파일 전체를 연속 기록으로 가정하지 않는다.
3. **정상 자료도 가변 DLC다.** 정상 frame에서 DLC 2·5·6이 관측된다. 공격 T는 이 파일에서 모두 DLC 8이다. DLC 8만 허용하거나 CSV를 고정 12열로 읽으면 정상 입력을 잘못 처리한다. Fuzzy 이름만으로 DLC·reserved 오류를 단정할 수 없다.
4. **정상 로그는 약 8분 26초다.** 유효 구간은 506.436571초다. 반복해 정상 30분의 독립 표본을 확보했다고 표현하지 않는다.
5. **정상 ID 목록이 완전하다고 보장되지 않는다.** 별도 정상 로그의 ID는 27개지만 Fuzzy의 R에는 그 목록에 없는 ID 11개·544 frame이 있다. `0x7E8/0x7E9`도 포함된다. 이 목록을 즉시 완전한 allowlist로 확정하면 라벨이 정상인 입력도 미등록으로 분류할 수 있다.

공통 suffix 시작 행(1-based)은 DoS 2,774,704행, RPM 3,730,635행, gear 3,552,075행, Fuzzy 2,947,793행이다. 모든 파일에서 첫 공통 시각은 `1478200727.419470`, 마지막 시각은 `1478201209.058944`다.

## 공격별 관측과 적용 한계

| 대상 | 관측 | 이 자료로 확정할 수 없는 것 |
| --- | --- | --- |
| DoS | T 587,521개가 ID `0x000`, payload `0000000000000000` | 가상 CAN에서 물리 arbitration DoS 성공, 정상 ID에만 정의한 기존 SIL 횟수 임계값의 자동 적용 |
| RPM Spoofing | T 654,897개가 ID `0x316`, payload `452924ff292400ff` | DBC·신호 배치·단위·허용 범위 없이 실제 RPM이나 물리 범위 초과 판정 |
| gear Spoofing | T 597,252개가 ID `0x43F`, payload `014560ff6b000000` | 실제 기어 인코딩·허용 상태 범위 판정 |
| Fuzzy | T 491,847개가 ID `0x000~0x7FF` 전체에 분포. 모두 DLC 8 | reserved·애플리케이션 CRC·counter 위반 판정 |

별도 정상 로그의 `0x316`·`0x43F` 간격 중앙값은 각각 10.002ms·10.000ms이고, 두 ID의 1초 peak는 101 frame이다. RPM 파일의 `0x316` 전체 peak는 985 frame, gear 파일의 `0x43F` 전체 peak는 969 frame이다. 이는 주기·빈도 규칙 검토 근거이며, 아직 정책·탐지율·오탐 합격선으로 채택하지 않았다.

HCRL은 A1·A3·A4의 **참고 공격 자료**로 활용할 수 있지만 위 조건을 고려해야 한다. 특히 A4 물리 범위, A5 CRC, A6 counter는 이 차량의 공개 정의가 추가로 필요하다. A7 Replay·A8 Suspension 및 B2·B3의 전용 정답도 이 배포에서 확보했다고 주장하지 않는다. `T/R`은 주입/정상 frame 구분이며 공격 영향 구간의 정답과 다르다.

정상 로그도 전체 1초 peak가 1,960 frame이며 공격 CSV는 2,349~2,738 frame이다. 전체 스트림의 원래 속도 재생과 프로젝트 공격/재생 도구의 1,000 frame/초 제한을 동시에 항상 만족할 수는 없다. 재생 속도·입력 구간·공백 처리와 분할 정책은 별도 결정 후 적용한다. 이번 분석에서는 원본 제거·재라벨링·학습·평가 분할을 수행하지 않았다.

## 로컬 결과와 재현

실행 식별자: `IDS/docs/results/20261124_hcrl_profile/`. 이 폴더는 프로젝트 결과 보관 정책에 따라 Git에 포함되지 않는다. 아래 명령과 파일은 해당 실행 환경의 로컬 원본·스크립트를 가리키며 새 checkout에 포함된 실행 도구를 뜻하지 않는다.

```bash
python3 IDS/docs/results/20261124_hcrl_profile/analyze.py

```

규정의 모니터링·시험·공격 분석 데이터 취지를 참고한 자료이며(`project.md` §10~11, 지정 R155 누적본 §7.3.6·7.3.7), 이 결과만으로 R155 적합성·실차 IDS 성능·1초 탐지 합격·IDPS 차단 효과를 주장하지 않는다.
