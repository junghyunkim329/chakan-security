# HCRL 룰 기반 IDS — 근거와 임계값 검토

기준일: 2026-11-24

상태: 실차 자료·논문·공식 지침과 원본 관측 결과를 대조한 근거 정리. 아래 정상 자료 보정 방식은 사용자 선택 대기인 구현 제안이다. IDS 구현·성능 검증을 완료했다는 문서가 아니다.

2026-11-24 후속 사용자 확정: AutoHack을 주 데이터셋으로 쓰며, 실제 데이터가 기존 프로젝트 가정과 충돌하면 실제 데이터를 우선한다(`project.md` §2.1.1). 이 문서는 비교용 HCRL의 측정값과 제안이며 AutoHack의 ID·임계값으로 전용하지 않는다. 기존 SIL의 3배 기준 유지를 위한 선택 요구는 실제 데이터 우선 원칙으로 대체한다. 아래 구체 보정·평가 분할을 실행·검증했다는 뜻은 아니다.

## 1. 근거를 적용하는 원칙

**탐지 특성을 고른 근거와 숫자를 정한 근거를 분리한다.** 논문에서 CAN 수신 간격이 유용하다고 확인했더라도 그 논문의 차량에서 사용한 임계값이 HCRL 차량의 사양이 되지는 않는다. 이 프로젝트의 자체 CAN CRC/counter·물리 범위도 외부 HCRL 데이터에 옮기지 않는다.

실제 HCRL 입력의 출처·hash·품질 분석은 [HCRL 원본 분석](hcrl-file-profile.md)에 있다. 원본은 보존하며 이 문서 작성 과정에서 frame 제거·재라벨링·새로운 평가 분할을 적용하지 않았다.

## 3. 제안한 네 가지 룰과 이유

룰은 공격 이름을 맞히는 분류기가 아니라 **관측 프로파일을 벗어났다는 사실**을 보고한다. 여러 룰이 같은 frame에 걸릴 수 있다. `T/R`, 공격 파일명, 알려진 공격 payload를 탐지 입력이나 조건으로 사용하지 않는다.

| 룰 | 제안 판정 | 선택 이유·근거 | 경계와 한계 |
| --- | --- | --- | --- |
| 미관측 ID | 정상 보정 자료의 ID 집합에 없음 | S2의 ID 검사를 참고하고 S3의 실제 입력 ID와 대조 | 완전한 OEM allowlist가 없으므로 “비인가 ECU 확정”이 아니라 “프로파일 미관측 ID”로 보고 |
| ID별 DLC 불일치 | 등록된 ID이지만 정상 자료에서 본 DLC 집합 밖 | S2의 DLC 검사. 실제 HCRL에는 정상 DLC 2·5도 있어 일괄 DLC 8 검사는 부적절 | 실제 frame 길이 불일치 같은 입력 오류와 구분. 정의가 없는 reserved bit 검사는 넣지 않음 |
| 과도하게 짧은 수신 간격 | 같은 ID의 직전 관측 frame과 간격이 정상 관측 최소값 미만 | S1의 시간 간격 특성, S2 §8.2.3.4의 주입에 따른 간격 변화 | 수신 간격은 ECU 처리와 logger jitter의 영향을 받음. 첫 수신에는 비교 전 값이 없어 이 룰을 판정하지 않음. 부정 frame 다음의 정상 frame도 짧아 보일 수 있음 |
| ID별 과다 횟수 | `(t−1초, t]` 수신 건수가 정상 자료의 동일 window 최대값 초과 | S2의 rate 검사와 기존 프로젝트 1초 관측 단위. 단일 짧은 간격과 지속 빈도 증가를 함께 관측 | 1초는 기존 프로젝트 선택값. 초과가 유지되는 동안 정상 R frame에도 이상 window가 연결될 수 있어 frame별 FP를 숨기지 않음 |

미관측 ID에 정상 주기나 최대 횟수를 0으로 가정하지 않는다. 기준이 없는 간격·횟수 룰은 그 ID에 적용하지 않고 미관측 사실을 기록한다. 알려진 정상 ID의 프로파일도 평가 중 자동 확장하지 않는다. 원본 CSV 형식 검사에 실패한 입력은 파싱 실패로 보고하며 정상 데이터나 공격 정답으로 만들어 넣지 않는다.

## 4. 임계값을 정상 관측 경계로 제안한 이유

HCRL 정상 로그 전체에서 확인한 범위 안의 입력을 추가 근거 없이 이상으로 선언하지 않기 위해, 첫 비교 기준으로 **최소 관측 간격과 최대 관측 횟수**를 제안한다. 임의로 5ms·100frame 같은 모든 ID 공통값을 넣거나 공격 파일에서 가장 성능이 좋아지는 값을 고르지 않는다.

이 방식 자체도 **프로젝트의 실험 정책 제안**이다. 논문이 이 데이터의 min/max 값을 지정한 것이 아니며, 표본에서 발견되지 않은 정상 상태에는 오탐이 생길 수 있다. 최소 간격의 낮은 outlier나 최대 횟수의 높은 outlier 때문에 미탐이 생길 수도 있다. 보정 자료에서 오탐이 없다는 결과는 수치 산출 방식의 결과이며 독립 검증 성과가 아니다.

| ID | 정상 자료의 허용 DLC | 최소 관측 간격 | 간격 중앙값 | 1초 최대 관측 횟수 |
| --- | --- | ---: | ---: | ---: |
| `0x316` | 8 | 5,667µs | 10,002µs | 101 |
| `0x43F` | 8 | 6,491µs | 10,000µs | 101 |
| `0x2B0` | 5 | 7,748µs | 10,007µs | 101 |
| `0x5F0` | 2 | 46,458µs | 49,999µs | 21 |
| `0x5A0` | 8 | 995,126µs | 999,120µs | 2 |

출처는 앞선 원본 분석의 `profile.json`이며 위 숫자는 **측정 결과**다. normal txt SHA-256은 `efbbafbf8e965c0d2f75eb97f1d118d0ae1c4b9f3077a6c4c000a26eb5be97ea`다. CSV의 공격 T/R을 보정에 추가해 이 숫자를 바꾸는 것은 제안에 포함하지 않는다.

비교 가능한 다른 안은 기존 SIL의 **1초 예상 횟수 3배 초과**를 유지하는 것이다. 정상 주기를 HCRL 자료에서 산출해 적용하더라도, 그 3배 배수는 기존 프로젝트 선택이며 해당 HCRL 실차나 S1 논문이 정한 값이 아니다. 데이터셋용 관측 경계 방식과 기존 SIL 방식은 섞지 않고 별도 정책으로 명시해야 한다.

## 5. 데이터 보정·평가의 제안 경계

- 보정: 별도 `normal_run_data.txt`의 유효 988,871 frame만 사용한다. 불완전한 마지막 1행은 원본과 오류 기록에 보존한다.
- 보정과 평가를 구분: 같은 정상 자료를 다시 읽은 결과를 독립 정상 검증으로 보고하지 않는다.
- 정상 평가 후보: 네 공격 파일에 공통으로 있는 정상 suffix 891,068행을 **한 번만** 사용한다. 보정·수치 조정에는 사용하지 않는다.
- 공격 평가 후보: 각 CSV에서 공통 suffix 전의 원본 prefix를 평가한다. suffix는 원본에서 삭제하지 않고 평가 선택 범위와 hash로 추적한다.
- T/R은 사후 frame별 confusion matrix에 사용한다. 기록 공백을 공격 시작·중단 정답으로 바꾸거나, R frame까지 공격 영향 구간으로 재라벨링하지 않는다.
- 기존 탐색 분석에서 이미 공격 파일 통계를 확인했으므로 엄격한 blind holdout 성능이라고 부르지 않는다. 결과는 이 HCRL 입력에 대한 개발·평가 결과로 한정한다.
- 룰별 결과와 룰 합집합 결과를 함께 보고한다. FP·FN과 데이터 품질 오류·보정 coverage 부족을 구분하며 알려지지 않은 정상 ID 11개·544 frame을 감추지 않는다.
- 이 데이터에는 공식 attack episode 라벨을 확보하지 못했으므로, 임의의 시간 간격으로 300개 공격 episode를 만들어 “각 공격 1초 이내 탐지” 합격을 선언하지 않는다.

이 분할과 임계값 정책은 `AGENTS.md`의 Missing decisions 및 `project.md` §2.1에 따라 사용자 결정 후 적용한다. 이번 근거 수집에서는 새 분할을 실행하거나 IDS 탐지 성능을 측정하지 않았다.

## 6. 이번 HCRL 룰에 포함하지 않을 항목

- 물리 RPM·기어 범위: OEM 신호 배치·단위·범위 근거 없음. 공격 이름이나 `FF` byte만으로 판단하지 않음.
- 애플리케이션 CRC·counter·reserved: 이 차량의 보호 형식 근거 없음. 프로젝트 자체 byte 6·7 프로파일 적용 금지.
- Suspension: 기록 공백·파일 종료와 실제 ECU 송신 중단을 구분할 ground truth 부족.
- Replay 확정: 반복 payload나 파일 간 중복만으로 공격자의 재전송을 확정할 수 없음. S4를 잔여 위험 설명의 근거로 사용.
- 자동 차단·CAN 송신·대시보드 제어: 현재 요청은 파일 입력 IDS다. 기존 대시보드 모니터링 권한과 향후 IDPS 결정 절차 유지.

## 7. 증거 연결에 필요한 구현·시험 항목

확정된 정책은 원본·보정 구간 hash와 수치 산출식을 가져야 한다. 이벤트에는 원본 위치·ID·관측값·해당 임계값·적용 정책을 연결한다. S5·S6은 분석 가능한 기록을 남기는 방향의 근거이며 특정 파일 형식의 근거는 아니다.

구현 이후에는 경계값의 바로 전/같음/초과, 1초 window의 열린 왼쪽 경계, ID별 상태 분리, 첫 수신, 정상 DLC 2·5, label 독립성, timestamp 오류, 원본 손상·파싱 실패와 보정/평가 중복 금지를 시험한다. 정상 수치 재현과 공격 파일 평가는 구현 후 별도 실행 증거로 이 문서에 연결한다.
